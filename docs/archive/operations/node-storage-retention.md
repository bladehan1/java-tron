# ARM 节点存储保留规则

来源：用户 2026-10-27 明确要求。适用于 ARM-001 的完整节点数据集及同步速率对比副本。

长期只保留：

1. 原始快照。
2. StateRoot 建立后的快照。
3. 一套当前节点数据。实际路径从当前 unit、PID 和配置读回，不能按旧目录名称判断是否废弃。

只有同步速率对比允许临时增加完整节点副本。开始前登记候选、输入、额外数据路径、空间预算、
容量保护及回收责任；对比成功、失败、中止或取消后均必须回收额外数据，确认回到两份快照加一套节点数据。

部署、冷重开及方便回退不能默认增加完整节点副本。必要的源码、JAR、配置、日志、指标和小体积控制文件证据可保留。
测试临时文件也须回收，不能通过改名绕过完整节点副本限制。

清理必须使用核验过的绝对路径白名单：

- 核对两份快照及当前数据的身份，排除它们以及祖先路径。
- 确认无活动进程、打开文件、工作目录或嵌套挂载引用，检查软链接边界。
- 保留对比结果、日志和控制文件摘要，再删除退役数据。
- 删除后复核保留身份、服务状态、实际可用空间及完整节点数据集数量。
- 以 `df` 实测空间变化；XFS reflink 的表观占用不能相加视为物理释放。
- 保留 30 GiB 容量保护，不通过降低保护线或删除保留快照维持运行。

执行台账须记录当次主机、时间、精确路径、候选身份和前后核对结果；历史路径不构成当前保留授权。
