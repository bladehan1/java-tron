范围：完成两项 P1，并将此前未发布的目录整理一并验证、提交和部署。

## Serving 持久格式

新增 [ServingIndexRecordCodec](../../../chainbase/src/main/java/org/tron/core/db2/archive/serving/format/ServingIndexRecordCodec.java)
与 [ServingIndexKeyCodec](../../../chainbase/src/main/java/org/tron/core/db2/archive/serving/format/ServingIndexKeyCodec.java)。
记录 codec 集中 descriptor、coverage、inline/paged metadata、epoch page 与 checksum；key codec 集中 exact 和转义 range key。
两者不持有 Store、文件句柄或发布权限。

原 generation 继续拥有读取、构建、租约和发布；原 Descriptor、Coverage、KeyMeta 类型和构造权限保留。
codec 解码通过调用方工厂创建原对象，编码通过只读视图读取值，不增加逐条对象包装，也不公开内部数组。
Descriptor/coverage 编码使用已有防御复制 getter，会产生固定长度摘要副本；不将此描述为零分配。
原 package API 继续转发，格式版本3/4/5、校验、排序及错误拒绝语义保持。

`PersistentServingKeyIndexGeneration` 从2151行降至1909行；字节布局移出，不将纯格式代码与 native Store 生命周期混放。

## Physical journal 管理

新增 [PathStatePhysicalJournals](../../../chainbase/src/main/java/org/tron/core/db2/stateroot/physical/PathStatePhysicalJournals.java)，
集中 journal 索引缓存、全量校验、固定 oracle 窗口、精确祖先链及 count/byte 保留策略。
原 StoreSet 私有持有该对象，继续在原同步入口内调用；每次打开增加一个管理对象和一个文件能力适配器。

文件读取和 durable delete 由 StoreSet 提供的私有适配器转发原 MetadataFile 操作。
管理对象不导出 native Store 或故障钩子，发布、participant/super 数据写入及 CURRENT/INTENT 次序仍由原所有者负责。
保留旧索引懒加载、oracle 强制读盘、重复 child 拒绝，以及删除成功后才移除缓存条目的次序。

`PathStatePhysicalStoreSet` 从2851行降至2672行。缓存热路径和 bootstrap 原生写入没有随本片改写。
